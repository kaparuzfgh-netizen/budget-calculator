# CLAUDE.md

Правила проекта для Claude Code. Полный технический реестр правил (№1–20)
живёт в [AGENTS.md](AGENTS.md) и **обязателен**; здесь — как мы работаем с
владельцем и сжатая выжимка. При конфликте приоритет у AGENTS.md.

@AGENTS.md

## Проект

Budget Companion — мультипользовательский Telegram-бот + Mini App личных
финансов на Cloudflare (v2; legacy Apps Script удалён, ADR-0001).

- `apps/api` — Cloudflare Worker: TypeScript strict, Hono, D1, cron, zod,
  vision (Gemini → Groq), FX (Frankfurter). Тесты — vitest в workerd.
- `apps/web` — Mini App: Vite + Preact + Tailwind v4, раздаётся тем же
  воркером (Workers Static Assets).
- `scripts/` — setup / release / webhook (Node ESM). `docs/` — архитектура,
  ADR, UX-навигация, BACKLOG.

## Как мы работаем (владелец — не разработчик)

**Роли.** Владелец только: (1) ставит задачи простыми словами, (2) отвечает
«Да/Нет» на планы, (3) нажимает «Разрешить» в окошках. Всё остальное —
код, проверки, коммиты, релиз, доки, порядок в файлах — делает Claude сам.

**Режим: ТЕСТОВЫЙ** (бот пока в тесте, реальных данных нет).
- ТЕСТОВЫЙ: после зелёного `npm run check` Claude сам коммитит, пушит в
  `main` и выкладывает (`npm run release`), затем сообщает результат.
- БОЕВОЙ (включается фразой владельца «включи боевой режим» — тогда Claude
  меняет эту строку): перед выкладкой Claude спрашивает «Да/Нет».
- В ЛЮБОМ режиме сначала спрашивать: удаление данных, любые секреты и ключи,
  необратимые правки живой базы, `git push --force`, платные сервисы.

**Формат каждого ответа — простым языком, без жаргона.** Незнакомый термин —
в скобках одной фразой. Итог задачи:
1. **Что сделано** — 1–3 строки по-человечески.
2. **Что изменится для пользователей бота** — или «ничего не видно».
3. **Как проверить** — 1–3 шага в Telegram/Mini App (если применимо).
4. **Что нужно от вас:** — ровно одно из: «Ничего — всё готово» / «Ответьте
   Да или Нет: <вопрос>» / «Нажмите «Разрешить» в окошке — оно просит <что и
   зачем>». Блок обязателен в конце каждого ответа.

**Окошки разрешений.** Перед командой, которая может вызвать окошко, одной
фразой сказать, что сейчас будет и можно ли смело нажимать «Разрешить».
Типовые команды (проверки, тесты, коммит, push в `main`, релиз) разрешены
заранее и окошек не вызывают; всё остальное — окошко, и это нормально.

**Словарь для владельца (объяснять по запросу и при первом упоминании):**
- *Коммит* — «сохранение версии» кода в истории. *Push* — отправка на GitHub.
- *Релиз/выкладка (деплой)* — обновление живого бота; делается командой
  `npm run release` (проверки → база → выкладка → проверка живости).
- *PR (pull request)* — предложение изменений. Мы сами PR не используем
  (пишем прямо в `main`); PR приходят только от бота зависимостей Dependabot
  (обновления библиотек) — их разбирает Claude: мелкие (patch/minor) при
  зелёных проверках вливает сам (в тестовом режиме), крупные (major) —
  объясняет и спрашивает.
- *Миграция* — изменение структуры базы; всегда новым файлом, старые не трогаем.

**Задачи.** Владелец описывает идею словами → Claude заносит в `TASKS.md`
(`[REVIEW]`) и сам ведёт по конвейеру. Владельцу остановки только две:
утвердить план (`[DESIGN]`→`[READY]`; план — коротко: что получится, что
изменится для пользователей, риски, вопрос «Утверждаете?») и, в боевом режиме,
выкладка. Остальные стадии идут без вопросов. Запрос «что происходит?» —
команда `/status` (человеческий отчёт).

### Конвейер задач

Единый источник задач — [TASKS.md](TASKS.md) (детальный бэклог продукта —
`docs/BACKLOG.md`; при закрытии пункта обновлять оба).

```
[REVIEW] → [DESIGN] → [READY] → [DOCS] → [DONE]
```

| Статус | Смысл | Кто | Выход |
|---|---|---|---|
| `[REVIEW]` | идея, риски не проверены | `advisor` | риски, вердикт go/no-go |
| `[DESIGN]` | нужен план | `architect` | план в `ARCHITECTURE_PLAN.md` → владельцу на «Да» |
| `[READY]` | план утверждён | `executor` | код + тесты, `check` зелёный |
| `[DOCS]` | код готов, доки отстают | `documenter` | README / `.env.example` / docs по `git diff` |
| `[DONE]` | всё сделано | — | коммит+выкладка (по режиму); план удаляется из `ARCHITECTURE_PLAN.md` |

1. Статус меняет тот, кто завершил стадию, одной правкой `TASKS.md`.
2. Стадии не перепрыгиваются; тривиальная правка (опечатка, 1 файл) — сразу `[READY]`.
3. `executor` не отступает от плана: не работает — назад в `[DESIGN]` с пояснением.
4. Тяжёлые стадии запускать субагентами (их рабочий контекст не засоряет основную сессию).

### Контекст и сессии (автоматизация)

- **Одна задача — одна сессия.** Состояние хранится не в памяти чата, а в
  `TASKS.md` → блок «Сейчас» (что сделано, следующий шаг, ждём ли владельца).
  Claude обновляет его после каждой стадии и перед паузой.
- **Старт любой сессии:** Claude первым делом читает `TASKS.md` («Сейчас» и
  открытые задачи) и `git status` — этого достаточно, чтобы продолжить с места.
- **Конец задачи (`[DONE]`, закоммичено):** Claude пишет «Задача закрыта.
  Следующую лучше начать в новой сессии — ничего не потеряется, состояние в
  TASKS.md» и предлагает кнопку «Новая сессия». Владельцу — один клик
  (или `/clear` в строке ввода).
- **Контекст заполнился (длинная сессия):** Claude обновляет «Сейчас» и сам
  предлагает новую сессию; встроенное авто-сжатие — страховка, не замена.
- Не просить владельца копировать/пересказывать прошлый контекст — всё берётся из файлов.

## Команды

| Команда | Что делает |
|---|---|
| `npm ci` | зависимости (workspaces `apps/*`) |
| `npm run check` | lint + typecheck + тесты api/web + сборка web. **Обязательно перед коммитом** |
| `npm test` / `test:api` / `test:web` | тесты |
| `npm run dev -w apps/api` | локальный воркер + D1 |
| `npm run release` | check → web → миграции D1 → deploy → /health |
| `npm run wrangler -- <cmd>` | wrangler из workspace apps/api |

Только владелец (браузер/секреты): `wrangler login/logout`, `wrangler secret put`,
секреты CI. Claude в таких случаях пишет точную инструкцию в 2–3 шага.

## Конвенции (выжимка — детали в AGENTS.md)

- **Workers ≠ Node:** в `apps/api` только Web API; без `process/fs/Buffer/node:*`.
- **Tenant (правило 3):** БД только через `scoped(env.DB, userId)` в
  `db/repo.ts` (части — `db/scoped/*`); каждый запрос с `WHERE user_id = ?`,
  мутации по id — `WHERE id=? AND user_id=?`. Сырой `db.prepare` вне
  `db/repo.ts` и `db/scoped/*` запрещён. Новый эндпоинт/запрос ⇒ тест «A не
  видит B». `user_id` — никогда не вход клиента.
- **Деньги:** INTEGER minor units в D1 (количества и цены инвест-позиций — десятичные строки, правило 21); домен (`src/domain/`) — чистые функции
  без I/O, float, `toMinor/fromMinor` на границе repo; «сегодня» — параметром.
- **Шифрование (правило 19):** новая текстовая/денежная колонка пользователя
  ⇒ запись в `FIELDS` (`db/crypto.ts`), без сырых WHERE по ней.
- **Миграции:** только новые `apps/api/migrations/NNNN_name.sql`
  (сейчас последняя — 0024), старые иммутабельны.
- **Валидация:** zod на каждом входе; Mini App API `/api/tma/*` — Bearer JWT,
  `client_id` для идемпотентности, те же правила, что у бота.
- **Секреты и логи:** ничего секретного в git и URL; в логах вебхука —
  только `update_id` и код ошибки (правило 10). Файлы `.env`, `.dev.vars` не читать.
- **Навигация бота:** сначала `docs/ux/navigation.md` + `screens.json`,
  потом код; нав-ряды через `navRow()`.
- **Mini App UI:** цвета только токенами палитры (dark/light), literal
  `white|black/<alpha>` запрещён.
- Язык кода/идентификаторов — английский; UI, комментарии, коммиты и доки — русский.

## Субагенты и команды

Субагенты (`.claude/agents/`): `advisor` (opus, read-only+web) · `architect`
(opus, пишет только ARCHITECTURE_PLAN.md) · `executor` (sonnet, код+тесты) ·
`documenter` (haiku, доки по diff).

Slash-команды (`.claude/commands/`): `/task` (провести задачу по конвейеру),
`/status` (отчёт для владельца), `/check`, `/release`, `/new-migration`.
