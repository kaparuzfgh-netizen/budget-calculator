## 2. Находки

### [P1 — HIGH]

- [x] **P1-1. Cron: «ретрай в следующий час» не работает — напоминания и автопроводки теряются при единичном сбое**
  - Файл: `apps/api/src/services/reminders.ts:16` (комментарий-обещание), `:157` (weekly, `lp.hour === WEEKLY_HOUR`), `:176` (платежи/автопроводка/займы, `lp.hour === PAY_HOUR`), `:226-276` (автопроводка).
  - Проблема: при ошибке (сбой Telegram, D1, FX) claim снимается «чтобы следующий часовой прогон повторил», но все ветки срабатывают **только в один час** (10:00 / вс 20:00). В 11:00 условие уже ложно → повтора нет. Для автопроводки хуже: на следующий день `dueDateFor(...).d === lp.day` тоже ложно → **платёж месяца не будет проведён вовсе**, без уведомления. То же при пропуске cron-тика Cloudflare.
  - Риск: тихо «врёт» остаток кредита и статус «оплачено» регулярного платежа — ровно то, что автопроводка должна была предотвратить.
  - Решение:
    1. Окно вместо точного часа: `lp.hour >= PAY_HOUR && lp.hour < 22` (и `>= WEEKLY_HOUR` в воскресенье). Дубли уже исключены claim'ами.
    2. Автопроводка «догоняет»: проводить, если дата платежа этого месяца **≤ сегодня** и платежа за месяц нет (а не только `=== сегодня`).
    3. Защиту «удалённое не воскресает» перенести с дневного claim на **помесячный claim на объект**: `claimReminder('auto_post', 'd:<debtId>:<YYYY-MM>')` / `'c:<commitId>:<YYYY-MM>'`. Тогда догоняющая проводка не воскресит удалённую запись.
    4. Тесты: сбой в 10:00 → проводка в 11:00; пропущенный день платежа → проводка на следующий день с `event_on` = фактическая дата прогона (или дата платежа — выбрать и зафиксировать); удалённая автозапись не возвращается до конца месяца.

- [x] **P1-2. Уязвимая версия Preact в продовом бандле Mini App**
  - Файл: `apps/web/package.json` — `"preact": "10.26.9"`.
  - Проблема: GHSA-36hm-qxxp-pg3m (JSON VNode Injection, high). Эксплуатируемость у нас низкая (мы не рендерим JSON от пользователя как vnode), но это единственная high-уязвимость в коде, который реально уходит пользователям.
  - Решение: обновить в пределах мажора до `10.29.x` (выпущенной ≥7 дней назад), пересобрать, прогнать `npm run check` и ручной смоук Mini App.

### [P2 — MEDIUM]

- [x] **P2-1. Неограниченная выборка всех трат за всё время**
  - Файлы: `apps/api/src/tma/overview.ts:60`, `apps/api/src/bot/features.ts:244` (`runWeek`, в т.ч. из воскресного cron), `apps/api/src/tma/api.ts:156`.
  - Проблема: `repo.listExpenses()` без даты читает всю историю пользователя и конвертирует её по курсам, хотя `weeklyStatus` нужны только текущие неделя и месяц. Чтение D1 и CPU растут линейно со временем жизни аккаунта.
  - Решение: передавать `since = min(начало месяца, начало недели)` в таймзоне пользователя (`weekStartInTz`, `monthInTz`). Тест: траты прошлого года не влияют на ответ и не читаются.

- [x] **P2-2. Нет лимитов на число кредитов/займов + N+1 при построении списков**
  - Файлы: `apps/api/src/tma/debts.ts:190` (`POST /api/tma/debts`), `:389` (`POST /api/tma/loans`), мастера в `bot/debts.ts`/`bot/loans.ts`; `services/debts.ts:75` и `services/loans.ts:41` — запрос журнала на каждый объект.

  - Решение: лимиты (например, 20 кредитов, 100 займов, проверка и в боте, и в REST, как `maxCommitments`); журналы — одним запросом `WHERE user_id=? ORDER BY debt_id, event_on, id` с группировкой в памяти.

- [x] **P2-3. Создание кредита/займа в Mini App не идемпотентно**

## 3. Что проверено и в порядке (без действий)

- `POST /api/tma/auth`: HMAC «WebAppData», `auth_date` ≤24ч и не из будущего >5 мин, лимит длины 8192, rate-limit 20/10 мин по SHA-256(IP), одинаковый 403 для «нет пользователя»/«не онбоарден».
- Bearer-JWT на всех `/api/tma/*`; удалённый пользователь (`deleted_at`) получает 403 даже с живым токеном.
- Webhook: секрет обязателен (503 без него), сравнение constant-time, дедуп `update_id`, в логах только id и код ошибки.
- IDOR: все мутации `WHERE id=? AND user_id=?`, вставки событий через `EXISTS` по владельцу; чужой id → 404 (REST) / молча (бот); тесты изоляции есть.
- Секреты: токен бота только на сервере; во фронте нет `VITE_*`; JWT в памяти; CSP `connect-src 'self'`, `frame-ancestors` — только Telegram.
- Mini App: тема Telegram, safe-area, экраны загрузки/ошибки/«не из Telegram»/«нет доступа», reauth при 401 ровно один раз, блокировка кнопок на время запроса.
