# 📊 Продуктовый аудит Personal Finance Companion

Дата: 2026-10-24 · Роль: продуктовый аналитик · Формат: критичное исправлено в коде, остальное — на ревью владельца.

> **Статус реализации (2026-10-24):** по решению владельца реализовано —
> P0 целиком (№1 валютные push-алерты, №2 напоминания о списаниях, №3 понедельничный nudge);
> P1 целиком (№4 digest+savings rate, №5 вклады, №6 мультивалютный кэш, №7 сверка с банком);
> распознавание скрина остатка ипотеки со сверкой одной кнопкой;
> P2 №8 (алиасы категорий), №10 (MOEX — ручная цена), №11 (гид `/guide`);
> резервный AI-провайдер Groq; метрики №7 (лист Metrics, `/metrics`, digest).

## 1. Продукт в одной фразе

Личный финансовый движок для одного пользователя (мультивалютный экспат: доход EUR,
долги RUB, жизнь KGS, учёт USD), который сам считает план, следит за ипотеками,
напоминает о тратах и подсказывает тайминг конвертаций — за $0/мес.

Метрики успеха для N=1-продукта (не рост, а качество жизни):
- **Время обслуживания** в неделю: цель < 5 минут (сейчас ~2 мин: один скриншот в воскресенье).
- **Доверие к цифрам**: свежесть снапшотов, живые курсы, сверка с банком.
- **Действия по сигналам**: сколько ЧДП/конвертаций/DCA сделано по подсказке системы.

## 2. Что уже сильно (не трогать)

| Актив | Почему ценно |
|-------|--------------|
| Воскресная петля (скриншот → Gemini → лимиты) | ядро привычки, минимум трения |
| ЧДП-калькулятор «платёж ↓ vs срок ↓» с точностью банка ±50 ₽ | уникальная фича, редкая даже в платных приложениях |
| Арбитраж-монитор «вклад 16% vs досрочка 11.9%» | принимает решение за пользователя, а не просто показывает цифры |
| Каскад дельты бонуса 50/50 с целевыми долями | превращает переменный доход в автоматическое правило |
| Health-аудит (`securityAudit`) | продукт «сам сообщает», что заболел (webhook/триггеры/курсы/снапшоты) |
| $0-стек без единой платной зависимости | позиционирование выдержано полностью |

## 3. Критичное — ИСПРАВЛЕНО в этом аудите (коммит)

| # | Проблема | Почему критично | Решение |
|---|----------|-----------------|---------|
| 1 | Новый деплой GAS = новый URL → webhook молча умирает, бот замолкает | главный «молчаливый убийца»: пользователь думает, что бот работает | `securityAudit` сверяет URL webhook с текущим развёртыванием |
| 2 | GOOGLEFINANCE отдаёт #N/A → все конвертации тихо идут на резервные курсы из Config | подрыв доверия: цифры «примерные» без предупреждения | флаг `FALLBACK_USED` в `getFx_()` + предупреждение в `/status` + проверка в аудите |
| 3 | Пропавшие cron-триггеры (воскресный опрос, roll-forward) незаметны | умирает ядро привычки и актуальность долгов | аудит проверяет наличие всех 3 триггеров и свежесть снапшота Net Worth (>2 дней = ❌) |

## 4. Разрывы JTBD (jobs-to-be-done)

| Работа пользователя | Покрытие | Разрыв |
|---------------------|----------|--------|
| «Знать, сколько можно тратить» | ✅ сильно | — |
| «Не пропустить обязательные платежи» | ⚠️ частично | реестр есть, **напоминаний о датах списаний нет** (аренда 1-го, алименты 10-го, Сбер 25-го, Т-Банк раз в 2 недели) |
| «Гасить досрочно или на вклад» | ✅ уникально | сами вклады не учитываются как актив → Net Worth занижен |
| «Поймать выгодный курс» | ⚠️ pull-only | `/fx` по запросу; **push-алерта при входе курса в выгодную зону нет** — пользователь должен сам вспомнить спросить |
| «Видеть рост капитала» | ✅ есть | прогресс медленный и не «продаваемый» себе: нет savings rate и факт-vs-план |

## 5. Рекомендации (на ревью — БЕЗ изменений в коде)

### P0 — быстрые победы (высокая ценность / малые усилия)

| # | Идея | Гипотеза | Оценка усилий |
|---|------|----------|---------------|
| 1 | **Push-алерты по валютам**: daily-триггер проверяет перцентиль EUR→RUB/KGS; курс вошёл в топ-15% диапазона → «Хорошее окно конвертации», вышел из низших 15% → отбой тревоги | Самая денежная фича для вашего профиля: разница курсов 3–5% на платежах 80 тыс. ₽/мес = 30–60 тыс. ₽/год | ~1–2 ч (логика уже есть в FXAnalytics, нужен только триггер+порог) |
| 2 | **Напоминания о списаниях** за 2 дня: «25-го Сбер спишет 44 282 ₽ — пополните счёт» | Спасает от просрочек при мультивалютности (надо ещё и конвертировать заранее) | ~1 ч (данные в реестре + due_day) |
| 3 | **Понедельничный nudge**: если воскресный опрос без ответа — в понедельник 9:00 мягкое напоминание | Сохраняет петлю при пропуске недели (отпуск, забыл) | ~30 мин |

### P1 — стратегические (закрывают разрывы JTBD)

| # | Идея | Что даёт |
|---|------|----------|
| 4 | **Digest «факт vs план»** в последний день месяца: план из Monthly_Cycles, факт из Weekly_Expenses + автоплатежи, savings rate % | Замыкает месячный цикл: видно, куда утёк профицит; мотивация через видимый savings rate |
| 5 | **Вклады как актив**: лист Deposits (сумма, ставка, окончание) → в Net Worth и в арбитраж как «фактически размещено» | Net Worth становится полным; арбитраж из теории превращается в учёт |
| 6 | **Мультивалютный кэш**: CASH_USD / CASH_EUR / CASH_KGS вместо одного числа | Сейчас остатки в трёх валютах приходится сводить вручную |
| 7 | **Сверка с банком**: 1-го числа бот присылает балансы ипотек из движка и кнопку «✅ Совпадает / ✏️ Ввести факт» | Устраняет дрейф между автоплатежами и реальностью (главный риск точности) |

### Чего НЕ рекомендую

- **ML-прогноз курсов** — overpromise, ложное доверие; текущая статистическая модель с ±σ честнее.
- **Автосделки/подключение бирж** — ломает $0-позиционирование и добавляет API-ключи бирж (= новые секреты и риски).
- **Хостинг где-либо, кроме Pages/GAS** — см. выше.

## 7. Метрики, которые стоит ввести (P1, вместе с digest №4)

- Weekly response rate: % воскресений с введёнными тратами (цель > 80%).
- Snapshot freshness: дней с последнего снапшота (цель ≤ 1; уже в аудите).
- Applied-каскад: % месяцев со статусом `applied` в Monthly_Cycles (цель 100%).
- Vision accuracy: доля записей, исправленных вручную (цель < 10%).
- Savings rate: (доход − все расходы)/доход за месяц (цель личная, отслеживать тренд).

Хранить в листе `Metrics` (пишет триггер), показывать в digest и Mini App.
