# Аудит 01 — Безопасность

Дата: 2026-10-25 · Роль: инженер по безопасности · Объект: текущий код (Apps Script + Mini App) и целевая модель «5 пользователей».
Метод: ревью архитектуры и ключевых файлов (`TmaApi.gs`, `Code.gs`, `SheetService.gs`, `TelegramService.gs`, `VisionParser.gs`, `mini-app/index.html`, CI). Динамическое тестирование не проводилось — проект ещё ни разу не запускался.
Соглашение: «подтверждено» = видно в коде; «проверить» = вывод по документации платформы, требует проверки в рантайме.

## Контекст изменения модели угроз

Прежний `SECURITY.md` написан для **одного** владельца. При 5 пользователях появляются новые активы и угрозы: чужие финансовые данные (мы становимся их хранителем), изоляция данных между пользователями, согласие на передачу скриншотов внешнему AI. Часть прежних «✅» перестаёт быть достаточной.

## Mini App: принятые риски и меры (веха E)

**Принятые риски:**
- **`telegram-web-app.js` без SRI/integrity** — загружается только с
  `https://telegram.org` (под наш CSP `script-src 'self' https://telegram.org`).
  Подставной хост исключён CSP; компрометация самого telegram.org — доверенный
  риск, альтернативы (self-hosted копия) теряют обновления API.
- **JWT 12 ч без отзыва** — валидный токен живёт до exp; отзыва нет (нет
  хранилища сессий). Смягчение: токен выдаёт только tg_id, резолвится в
  пользователя на каждый запрос — удалённый (`delete_me`) получает 403, а не данные.
- **Replay initData в пределах 24 ч** — тот же initData можно переиспользовать
  до истечения `auth_date`. Принят: initData только выдаёт сессию, не пишет данные.
- **Rate-limit по IP-хэшу** — 20 попыток / 10 мин на POST `/api/tma/auth`;
  IP хранится только как SHA-256 hex. Брутфорс подписи нереален без токена бота.

**Меры:** `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
`Cache-Control: no-store` на `/api/*` + `/telegram/*`; CSP на HTML
(`default-src 'self'`, `frame-ancestors telegram.org` — Mini App живёт во фрейме
Telegram, `X-Frame-Options` не ставим осознанно); одинаковый текст 403 для
«нет пользователя» / «не онбоарден»; `auth_date` не старше 24 ч и не из будущего
>5 мин.
